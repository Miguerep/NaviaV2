# NaviaV2 Action Plan

This document outlines the actionable steps to resolve the 7 identified issues in the NaviaV2 application, referencing the current Flutter (Frontend) and FastAPI (Backend) architecture.

## 1. Map does not center on the specified onboarding location
**Context:** The `osm_map_view.dart` is likely initializing with default coordinates instead of the user's selected destination.
**Action Steps:**
- **Frontend (`app/lib/screens/itinerary/itinerary_screen.dart` & `osm_map_view.dart`):** Retrieve the selected destination coordinates (`start_lat`, `start_lng`) from the `TripProvider`.
- Pass these coordinates to the map controller's initialization method (e.g., `initMapWithUserPosition` or `changeLocation`).
- Ensure the map widget rebuilds or animates to the new camera position once the trip data is successfully fetched or updated.

## 2. App does not save state when closed
**Context:** The app currently relies entirely on in-memory state management (Providers) and loses the active `trip_id` or user session upon termination.
**Action Steps:**
- **Frontend (`app/pubspec.yaml`):** Add a local persistence package like `shared_preferences` or `hive`.
- **Frontend (`app/lib/providers/trip_provider.dart`):** Upon successfully creating or loading a trip, save the `trip_id` to local storage.
- **Frontend (`app/lib/main.dart` or `app/lib/app/navia_app.dart`):** On app initialization, check for an existing `trip_id` in local storage. If it exists, route the user to the `ItineraryScreen` and fetch the trip data from the backend instead of starting at the onboarding screens.

## 3. TTS (Text-To-Speech) for places does not work
**Context:** The TTS service might be failing due to missing permissions, incorrect plugin initialization, or backend API issues.
**Action Steps:**
- **Backend (`backend/app/routers/narration.py` & TTS Service):** Verify that the TTS endpoint is correctly generating and returning the audio file/stream and not failing silently with 500 errors.
- **Frontend (`app/lib/services/speech_service.dart`):** Ensure the audio player or TTS plugin is correctly initialized. Add `try-catch` blocks to log any audio decoding or playback errors.
- **Frontend (Android/iOS configurations):** Double-check `AndroidManifest.xml` and `Info.plist` for any necessary network or background audio permissions.

## 4. Text box color matches the background (Text is invisible)
**Context:** The active or inactive fill color of the `TextField` or `TextFormField` is identical to the input text color, causing readability issues.
**Action Steps:**
- **Frontend (`app/lib/theme/navia_theme.dart`):** Locate the `InputDecorationTheme` inside your `ThemeData`.
- Explicitly define contrasting colors. For example, if the `fillColor` is dark, set the `TextStyle(color: Colors.white)` for the input text, and vice versa.
- Ensure `hintStyle` also has a contrasting, slightly faded color to distinguish it from actual input.

## 5. Fix city search in onboarding
**Context:** The search mechanism (likely using Nominatim via backend) might be broken due to improper state updates, lack of debouncing, or API structure mismatches.
**Action Steps:**
- **Frontend (`app/lib/screens/onboarding/destination_screen.dart`):** Ensure the `TextField` `onChange` callback uses a debounce timer (e.g., 500ms) to prevent spamming API calls.
- **Backend (`backend/app/features/api/osm_nominatim_service.py`):** Check the Nominatim API request. Ensure the `User-Agent` header is set (Nominatim blocks requests without valid User-Agents). Validate that the mapping of raw Nominatim data to the `PlaceResult` schema is correct.
- **Frontend (Error Handling):** Add a loading indicator and error states in the UI to notify the user if the search fails.

## 6. Responsive itinerary post-onboarding & initial prompt injection
**Context:** The initial itinerary generated by the AI needs to strictly follow the parameters selected during onboarding (dates, pace, interests, location).
**Action Steps:**
- **Backend (`backend/app/services/chat_service.py`):** Modify the system message prompt generation. Dynamically inject the specific details from the `Trip` database model (e.g., *"Create an itinerary for {destination} from {start_date} to {end_date}. The user prefers a {pace} pace and is interested in {interests}."*).
- **Frontend (`app/lib/providers/chat_provider.dart` & `itinerary_screen.dart`):** Ensure that as soon as the first SSE (Server-Sent Events) chunk arrives from the backend, the UI reactively updates. Use a `StreamBuilder` or listen to the `ChatProvider` to dynamically render the DayPlan/Stops as the AI builds them.

## 7. Change languages / Localization support
**Context:** The app is currently hardcoded to a single language and needs a robust i18n solution.
**Action Steps:**
- **Frontend (`app/pubspec.yaml`):** Add `flutter_localizations` and `intl` packages. Enable `generate: true`.
- **Frontend (`l10n` folder):** Create `.arb` files (e.g., `app_en.arb`, `app_es.arb`) to extract all hardcoded UI strings.
- **Frontend (`app/lib/main.dart`):** Configure `MaterialApp` with `localizationsDelegates` and `supportedLocales`.
- **Frontend (`app/lib/app/app_settings.dart`):** Add a state variable to track the selected `Locale` and allow the user to change it via a dropdown in the `ProfileScreen`. Ensure this locale is passed as a header to backend API calls if the AI/backend needs to respond in the selected language.
